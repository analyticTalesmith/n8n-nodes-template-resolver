# User docs

**Read by:** people using the product who do not know how it is built.
**Inputs:** the validated feature documents, the acceptance scenarios, the glossary and the design notes.

1. **Overview** - what the product does and the terms used, taken from the glossary.
2. **Getting started** - the setup and the first task, step by step.
3. **Tasks** - one entry per user goal: steps, expected result, and what to do when it fails.
4. **Settings** - each user setting, its default and what it changes.
5. **Troubleshooting** - known problems and their fixes, from the verification report.
6. **Glossary** - the product terms in the reader's words.
