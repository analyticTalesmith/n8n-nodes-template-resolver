## Findings

### f1: Unconditional pipe escaping double-escapes escape_md output inside table cells and splits the row again

- Class: drift
- Status: sustained
- Serves: m1: Before this change, a template author could make a pipe safe in a cell by writing ${{a|escape_md}}, because escape_md backslash-escapes '|'. The cell rendered as 'x\|y' and the table kept its column count. Now processCellsArray escapes every '|' again, so the cell becomes 'x\\|y'. GFM parses the '\\' as an escaped backslash, so the '|' that follows is a live column delimiter and the row gains an extra column. The fix changes behavior outside the named defect and breaks the very case c1 protects (the row keeps its column count) for already-escaped input.
- Raised in round 1; sustained 0, failed fixes 0
- Reproduction: resolveTemplate('{{TABLE}}{{ROW}}${{a|escape_md}}|z{{END_ROW}}{{END_TABLE}}', new Map([['a','x|y']]), {strictMode:false}). Before the fix this gives '| x\|y | z |' (two columns in GFM). After the fix it gives '| x\\|y | z |', which a GFM renderer splits into three cells ('x\', 'y', 'z'). Smallest fix: escape only pipes that are not already preceded by a backslash, for example content.replace(/\r?\n/g, ' ').replace(/(^|[^\\])\|/g, '$1\\|'), applied repeatedly or with a lookbehind (?<!\\)\|. Alternatively, have escape_md and cell escaping agree on a single escaping step.

### f2: The single-backslash lookbehind leaves a pipe unescaped when an even number of backslashes precedes it, which splits the row

- Class: drift
- Status: filed (0015-follow-up-the-single-backslash-lookbehin)
- Serves: c1: The new lookbehind (?<!\\)\| skips any pipe that has a backslash directly before it. That is correct for an odd-length backslash run, such as escape_md output or raw '\|'. It is wrong for an even-length run: in raw data like 'x\\|y' (two literal backslashes, then a pipe), GFM reads the two backslashes as one escaped backslash. The pipe then stays a live delimiter, so the row gains a column, which breaks c1. The rule should be: escape a pipe when the backslash run before it has even length, zero included.
- Raised in round 2; sustained 0, failed fixes 0
- Reproduction: resolveTemplate('{{TABLE}}{{ROW}}${{a}}|z{{END_ROW}}{{END_TABLE}}', new Map([['a', 'x\\\\|y']]), {strictMode:false}). The JS value is the characters x, \, \, |, y. The output is '| x\\|y | z |' with the pipe left unescaped, because the character before it is a backslash. Under GFM the cell scanner consumes '\\' as one escaped character, so the '|' that follows ends the cell. The row renders as three cells ('x\', 'y', 'z') instead of two. The smallest fix is to escape based on the parity of the backslash run, for example content.replace(/\r?\n/g, ' ').replace(/(\\*)\|/g, (m, b) => b.length % 2 ? m : b + '\\|').trim(). This keeps escape_md output, which always has an odd run before '|', unchanged and still escapes the case above.
