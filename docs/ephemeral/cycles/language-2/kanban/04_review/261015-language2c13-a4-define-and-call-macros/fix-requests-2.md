# Fix request, review round 2 (macros card)

## f5 (goal-risk, serves mc-output): hold each node's output as it is produced in a legacy TABLE-FOR text row

Failing scenario: `{{DEFINE a()}}` + `x`.repeat(100) + `{{END_DEFINE}}{{TABLE}}{{FOR xs AS x}}` + `{{CALL a()}}`.repeat(100) + `{{END_FOR}}{{END_TABLE}}` with `xs: [1]`, `maxOutputChars: 1000`, `render`: `limit-output`, but `stats.iterations` is about 101 (every call ran) instead of at most about 22. Also with `|` between the calls, and with calls mixed with text and variables on one line, in an IF inside the FOR, and at top level or inside an IF body.
Cause: in `collectRows` (`core/src/interpreter.ts`) the legacy (non-strict) path collects a run of inline nodes (Text, Variable, Ternary, Comment, Set, Call) and `flush()` visits the whole run (`run.map(visit).join("")`) before `addText` holds any cell, so the nodes of a run are not counted as they finish.
Smallest change: render the run through `renderChildren` in a trimming context (a legacy row text is trimmed: `text.trim()`, `cell.trim()`), for one node and for many, then split and add as today. Every legacy output stays exactly as it is; a template with no CALL behaves as at base.
Tests (one new block appended at the end of `tests/language/macros.test.ts`, no existing row changed, names start with `mc-output` or `mc-compat`): the repro above in four entries with `stats.iterations <= 22` (render); the same with `|` separators, text and variables around the calls, inside an IF in the FOR, and at top level and in an IF body; exactly-at-the-limit renders and one over fails; guard rows, probed on the base commit `5ddf88c` (export with `git archive`, outside the repo), for legacy text rows of a TABLE-FOR with a Variable, Text, Set, Comment and a pipe line, multi-line text, and a trailing-blank body at a small limit, so the output is unchanged.
