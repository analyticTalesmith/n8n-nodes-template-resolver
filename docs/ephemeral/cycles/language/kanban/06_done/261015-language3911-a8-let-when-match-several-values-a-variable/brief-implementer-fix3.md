## f3: WHEN names are a second, looser name rule
`WHEN_PATH` in `core/src/expressions.ts` accepts `limit-1`, `a-`, `a--b`, `a@b`. The language reads a hyphen as part of a name only between two ASCII letters (`joinsName`); `n-1`, `a-`, `a--b`, `1-a` are arithmetic, not names (ADR 0003: an item that is neither a literal nor a variable path is an error in every mode).
Fix: replace the regex by one small function (for example `isWhenPath(text)`) built on `joinsName`, in `expressions.ts`: segments separated by `.`, none empty; a name starts with a Unicode letter, `_` or `@`; later characters are Unicode letters or digits or `_`; a `-` is allowed only where `joinsName(text, i)` is true; `@` only as the first character of the whole path (so `@index0` and `@parent.index0` shaped names still parse, `a@b` does not); a plain number stays a number literal (parseLiteral runs first); `café`, `user.prénom`, `first-name`, `items.0` keep working. Rejected ones are a located `syntax-error` at the WHEN tag, in render, validate and analyze, every mode, and analyze lists nothing for them.
Rows (all four entries for runtime, plus validate and analyze rows): `limit-1`, `a-`, `a--b`, `a@b`, `-a`, `1-a`, `a.`, `.a`, `a..b` are syntax-errors at the WHEN line and column (also as a second list item and as a comparison operand: `{{WHEN > limit-1}}`); `first-name` and `café` still match. Include the lenient case from the review (`{{CASE x}}{{WHEN limit-1}}Y{{DEFAULT}}N{{END_CASE}}`, x empty, lenient): a syntax-error, not `Y`.

## f4: a trailing backslash inside quotes used to work
`{{WHEN 'C:\'}}` matched the text `C:\` before this card; `splitCommas` now treats a quote preceded by a backslash as escaped, so the tag fails with Unclosed quote. The spec says a WHEN quoted text is not unescaped.
Fix: for the WHEN parse only (conditions' `parseListLiteral` must behave exactly as today), a quote closes a quoted text when it is the same quote character and is followed, after optional spaces, by a comma or the end of the text, even if a backslash precedes it; otherwise a backslash before a quote still keeps it inside the text (`"a\"b"` stays one text, backslash kept). Add one option to `splitCommas` (not a second scanner) for this. Rows (all four entries): `{{WHEN 'C:\'}}` matches subject `C:\`; `{{WHEN "a\", "b"}}` matches subject `b` and subject `a\`; `{{WHEN "x\"y"}}` matches subject `x\"y`; a trailing-backslash value inside a comparison (`== 'C:\'`); and a condition guard row in the existing operators style is NOT needed (do not touch operators tests), but run them.
